0:40–1:40

The problem I experienced

SHOW: Stay on the homepage. Point to Documents and Courses while explaining.

The problem goes beyond finding lecture notes or past exams. Even official documents that students are expected to be able to access can be difficult to find and obtain.

I experienced this myself as a student. Finding the right document became an extra task, even though I simply needed it for my studies. Course materials shared through different channels created a similar difficulty.

That experience motivated this project. I wanted one organised place where students could find useful documents and learning resources, with continuity between academic years.

My research review also examined student messaging groups and learning platforms. It helped inform the design, while my personal experience explains the local motivation.

Explain the architecture

SHOW: The architecture diagram from your report. Point to each service while discussing it.

The interface uses React and Next.js. Next.js also provides the server routes and server actions, keeping the main application in one codebase.

Supabase supplies authentication and the PostgreSQL database. It also provides Realtime functionality and storage for images such as avatars and event artwork.

Cloudflare R2 stores learning resources, while PostgreSQL holds their metadata and classification.

During an upload, the server authorises the request and generates a signed upload URL. The browser transfers the file directly to object storage, avoiding passing the full file through the application server.

Downloads currently use public CDN URLs. The catalogue requires sign-in, but a shared file URL does not require a fresh application session.

A separate tools API generates wind rose and sun path diagrams for architecture work. These services form the cloud architecture supporting the interface.
